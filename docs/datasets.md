# Chhat training datasets

## roofseg: rooftop segmentation (our own model)

**What:** 256x256 satellite image chips of Lahore with binary building/rooftop masks,
built by us from open data. Used to train `models/rooftop_seg.pt` (our own U-Net).

**Sources:**
- Building footprints: **OpenStreetMap** (ODbL 1.0, © OpenStreetMap contributors),
  fetched via `api.openstreetmap.org` for three dense residential regions of
  Lahore, Pakistan:
  - **dha** (DHA-adjacent, ~31.470N 74.325E) — 161 chips
  - **dha5** (DHA Phase 5, ~31.462N 74.395E, 1,048 OSM buildings in probe) — 419 chips
  - **johartown** (Johar Town, ~31.470N 74.273E, 344 OSM buildings in probe) — 96 chips
  Model Town was probed but dropped: only 14 OSM buildings in the quadrant
  (too sparse to be useful).
- Satellite imagery: **Esri World Imagery** (z18, ~0.6 m/pixel), tile server
  `server.arcgisonline.com`. Used under Esri's terms for development.

**Build:** `scripts/build_roofseg_data.py` downloads OSM buildings per region,
stitches Esri tiles into a per-region mosaic (cached under
`data/roofseg_regions/<name>/`), rasterizes footprints to masks, chips
256x256 keeping 5-95% building coverage, merges regions, and splits 80/10/10
(seed 7).

**Size (2026-10-11, Wave 5):** 676 chips — train 540 / val 68 / test 68.
Reproducible with one script (`data/` itself is gitignored, 50+ MB).

**Honest limitations:**
- OSM footprints and Esri imagery were captured at different times: some masks
  are slightly misaligned or stale (demolished/built since mapping). This adds
  label noise; the model is therefore conservative and every prediction carries
  a confidence score (see `chhat/roofseg/`).
- OSM coverage is community-mapped: some real buildings are missing from masks
  (model may "find" buildings the mask missed — this is label noise, not error).
- Imagery is ~0.6 m/pixel: small structures (water tanks, mumty) are sub-pixel
  and cannot be segmented at this resolution.

**Why this instead of Massachusetts/WHU/INRIA:** those canonical datasets are
either offline (Toronto link dead), 8-16 GB (WHU/INRIA — too big for our box),
or behind logins. Ours is real, open, Lahore-specific, and reproducible with
one script.

## address-parser: Pakistani address NER (our own model)

Synthetic training data generated by `chhat/parser/generate_data.py` from
Pakistani address templates, including messy real-world styles. No external
dataset needed; templates are our own. Model: BiLSTM token tagger,
`models/address_parser.pt`.

**Wave 8 multi-city expansion:** 2,500 extra training addresses with
city-specific formats, round-robin across 4 cities (~625 each):
- **Karachi:** `R-123` house numbers, `Block 13, Gulshan-e-Iqbal`,
  `Khayaban-e-Ittehad` street names, `North Nazimabad` / `Clifton` blocks,
  DHA Phase 2-8
- **Islamabad:** `Sector G-13/2` blocks, bare sectors as colonies (`F-10/3`,
  `E-11/4`), `Margalla Town`
- **Rawalpindi:** `Satellite Town` blocks, `Bahria Town`, `Chaklala Scheme III`
- **Faisalabad:** `Madina Town` blocks, `DHA`, `Model City` / `Wadi-e-Sitara`

Held-out multi-city test: 600 addresses (different seed), entity F1 reported
separately in `models/address_parser_metrics.json` (`test_multicity`).
